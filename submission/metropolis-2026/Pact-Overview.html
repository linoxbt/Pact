Pact

Programmable authority for autonomous agents.

Submission overview · 12 October 2026 · Monad testnet

Executive summary

Pact is a programmable authority and economic accountability layer for autonomous agents. Developers connect an agent to registered API operations, give it a scoped integration key, and define owner grants and ordered policies. Pact checks each proposed action before forwarding it and records the result. For supported economic actions on Monad testnet, contracts constrain authority, reserve exact capacity and link a funded obligation to a checkable settlement receipt.

The problem

An API key or wallet lets an agent act, but does not by itself express who approved that action, its destination, its ceiling or the obligations it creates. Prompt instructions are not an enforcement boundary. Developers need a service boundary that can refuse disallowed execution and explain every decision.

What ships today

The Console includes Agents, Endpoints, Grants, Policies, API keys, Approvals and live Activity. Developers can register operations manually or through OpenAPI import. The gateway authenticates a scoped key, evaluates active grants and ordered policy rules, forwards allowed HTTP requests with vaulted upstream credentials, and blocks denied calls before the upstream. TypeScript and Python SDKs, curl examples and an MCP server expose the same API.

Economic path on Monad testnet

An owner-specific account and onchain grant bind agent, token, recipient, per-action ceiling and aggregate capacity. The contracts reserve exact action capacity, reject replay and enforce an approval threshold. The implemented obligation path covers one funded milestone: signed terms, escrow, evidence, a named verifier verdict, settlement and a receipt root. The public receipt API reports verification.valid = true for the linked testnet transaction set.

Evidence and limits

The October 8 exercise recorded 51 scenario checks plus two operational checks with a separately deployed Railway agent and a real model. It exercised allowed and denied gateway calls, approved transfers and a funded obligation. The actor expired on October 10 and its onchain grants were revoked. The historical receipt remains checkable. Private HTTP activity is an operator log, not a chain-anchored receipt. Recurring-contract liability valuation, mainnet use, independent real-world delivery verification and external KMS/S3 production configuration remain outside this demonstrated scope.

Use case and first users

A developer can begin with one agent, one protected GET endpoint and one ordered policy. The agent receives a Pact key, not the upstream provider credential. Allowed requests reach the service; denied methods or paths stop at the gateway. First users are agent developers protecting third-party APIs and Monad teams building service, treasury or procurement agents. Distribution begins through the repository, docs, direct builder outreach and design-partner sessions. These are target users, not claimed customers.

Architecture

Console / SDK / MCP → API registration and owner controls → scoped key + grant + ordered policy → gateway decision → protected upstream or Monad contract → activity / obligation / receipt. A key authenticates the integration but does not confer spending or signing authority. The owner remains explicit and auditable.
